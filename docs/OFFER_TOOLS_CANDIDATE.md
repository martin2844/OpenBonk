# Offer Tools integration candidate

Offer Tools requires the `unlimited_offer_tools` hook and is not compatible with OpenBonk 0.1.8. Do not publish its catalog entry until a compatible APK is available. Build the launcher ZIP with `python3 mods/tools/package_mod.py mods/offer-tools OUTPUT.zip`; imports are disabled by default. The adaptation covers virtual refresh, skip and banish counts only. Actual uses and their normal gold costs still accumulate; disabling does not undo gameplay effects.

The tested Android data target is SHA-256 `5e57197c6ed213095b3dc66fb518b9d1cfd6318d8961baed50a7a187383e445d`, 374365435 bytes. Reconstructing from the tested Linux and Windows input ZIPs produced the same target byte for byte. Embedded deltas cover the pinned compatible data from 0.1.1 through 0.1.8; 0.1.0 first uses the existing verified remote 0.1.0-to-0.1.4 patch, followed by the embedded 0.1.4-to-offer delta. The original OBB is retained. Version code 10 or later and `--obb-migration-library` are required for the packager to include the six validated patches.

The isolated Xiaomi candidate was installed over an isolated build of 0.1.8 with a test profile: the six profile files retained their hashes and the migrated OBB matched the target. Compatible source OBBs 0.1.0–0.1.7 were also migrated individually on the device, including the real 0.1.0 remote download; their original hashes remained unchanged. The exact Offer Tools ZIP was imported, enabled, and disabled in the dual-input test APK; a refresh in a short Forest run used the normal price and disabling removed the virtual counts. Chest Tracker and Run Metrics coexistence, banish, and two refreshes including normal gold deduction were separately checked in an embedded Android diagnostic; skip and chest banish were covered by Unity tests but not exercised end to end on device. Physical controllers and long runs remain untested.

The tested APK used an isolated application ID, debug signing and manually added migration assets and library in the final generated Gradle project. It is a private test artifact, not the production APK. Review, sign and validate the exact production build and ZIP before publishing. Local Unity workspaces, reconstructed OBBs and game inputs remain private.
