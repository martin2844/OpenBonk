# Toggle Everything (research prototype)

An independently written policy inspired by [ToggleEverything by Semibox / Slimaeus](https://thunderstore.io/c/megabonk/p/Semibox/ToggleEverything/). No upstream code or assets are included; no upstream license was identified.

While enabled, weapons, tomes and items are eligible for the game's normal activation controls even if they normally lack that eligibility. The existing Toggler shop requirement and other native availability rules still apply; this does not unlock or purchase anything. Characters and hats retain their native rules. Changes made through the game's Toggler are ordinary saved user choices. Turning the mod off and restarting restores native eligibility rules but does not erase those saved choices. This independent policy checks types at query time rather than mutating the shared data assets as the PC mod does.

Requires a future OpenBonk host with the `toggle_everything` hook; it is not in the public catalog. Launcher import and physical-controller navigation have not yet been tested. The PC original was inspected as source, not run for an end-to-end comparison.

An isolated Xiaomi IL2CPP build loaded the policy using a diagnostic manifest. The test used a newly generated profile for that package; only in that fixture, the native encrypted progression was updated with the game's `SimpleEncryptor` to set the Toggler shop level to 1. After completing a run to unlock the menu, touch controls disabled a weapon, a tome and an item. Firestaff remained disabled after backgrounding and restarting the app. With the policy disabled and restarted, its native card was active and the extra toggle disappeared; re-enabling the policy restored the saved inactive choice. The isolated app and profile were removed afterwards. This did not test launcher ZIP import or physical-controller navigation.

Editor checks cover the shop gate, the three eligible types, characters and hats, preservation of original always-toggle data, no data-asset mutation, saved inactive choices and the return to native rules. They also cover interaction with Unlock Everything: while both policies are enabled, the unlock override respects a native inactive choice; Unlock Everything alone retains its previous behavior. The PC mod was not run side-by-side, and this Android diagnostic used the policy with a manually edited manifest rather than the final launcher preference flow.
